Reading R: the ten things you need

# …
Everything after a # on a line is a note for humans. R skips it.
x <- 5
“Store the value 5 under the name x.” The arrow is how R saves things for later use.
name(...)
A function: a named operation that takes inputs in brackets and gives back a result, e.g. mean(x) returns the average of x. sprintf("%.4f", x) turns a number into text with four decimals; "\n" means “new line”.
function(...) { ... }
Defines a new, home-made function: a reusable recipe. Nothing happens when it is defined; the recipe runs only when it is later called by name. Here say() is one.
c(10, 40)
Combines values into a vector (an ordered list of values).
tibble / list
A tibble is a table: rows are observations, columns are variables. A list is a container that can hold anything, here tables of results; draws[["10"]] stores or pulls out the item named “10”.
dat$unvoting, dat[[v]]
Two ways of pulling one column out of a table; dat[[v]] uses the column whose name is stored in v.
NA, !is.na(x)
NA is R's code for a missing value; ! means “not”, so !is.na(x) means “x is not missing”.
for (n in sizes) {...}, replicate(reps, ...)
Repetition. A for loop runs the code once for each value in sizes; replicate runs it reps times and collects the results.
|>, ggplot(...) + ...
The pipe |> passes the result of one step on to the next (“and then”). In charts, + adds one layer or setting at a time.

19# Design choices, stated explicitly:
20#   - The population is the set of *observed* (non-missing) values, as asked.
21#     For unvoting that is 190 states; for article98 it is 216.
22#   - Sampling is *with replacement*. That is what makes the population an
23#     urn of fixed values that can be re-drawn, and it is the assumption under
24#     which sd / sqrt(n) is exactly right. If instead we sampled n distinct
25#     states (a simple random sample without replacement), the exact formula is
26#     (sd/sqrt(n)) * sqrt(1 - n/N), which is *smaller* by the finite-population
27#     correction; the difference is small here (N >= 190, n <= 40, so at most a
28#     21% shrinkage) but worth knowing. Both are reported at the end of each
29#     variable.
Lines 19–29

States the design choices: the population is the non-missing values (190 states for unvoting, 216 for article98), and samples are drawn with replacement. It explains that this is the setting in which sd/√n is exact, and that drawing without replacement would need the finite-population correction.

Check: “at most a 21% shrinkage” is wrong. With n = 40 and N = 190 the correction factor is √(1 − 40/190) = 0.89, an 11% shrinkage (the script itself prints 11.1% at the end). 21% is n/N, the share of the population sampled, not the shrinkage.
Good: the with/without replacement choice is stated and justified, which none of the other submissions did as clearly. It explains exactly why this script's simulation matches sd/√n while the scripts that sampled without replacement came out lower at n = 40.

223# Without replacement, the exact spread is (sd/sqrt(n)) * sqrt(1 - n/N), because
224# you cannot draw the same state twice, so the n draws are negatively
225# dependent. The sqrt(1 - n/N) factor is the finite-population correction: it
226# shrinks the standard error a little, because a sample without replacement
227# misses less of the population than one with. We sample WITH replacement, so
228# this is only a check on how much that choice could matter.
229say("\nFinite-population correction, if we had sampled *without* replacement:")
